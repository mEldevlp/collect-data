# screens.exe — утилита скриншотов для collect_audit.cmd

> **Промпт для нового чата:**
> «Прочитай `screens/PLAN.md` и приступай к реализации с этапа 1. Сначала реши открытые вопросы из конца плана (предложи варианты по умолчанию), потом действуй по этапам и после каждого этапа тестируй на виртуальных машинах.»

## 1. Контекст

- Репозиторий `collect_data`. Сбор данных делает `collect_audit.cmd` (cmd, Windows-1251, CRLF, ~2000 строк). Он создаёт папку `%ROOT%\%COMPUTERNAME%_%IP%` (переменная `OUT`) и вызывает разделы `:collect_*`, затем `:convert_utf8`.
- Отчёт строят `make_md.ps1` и `make_report_ib.cmd`. Скриншоты они пока не используют: `make_report_ib.cmd` ждёт, что скрин «Установленное ПО ИМЯ_IP» положат вручную.
- Сейчас скриншоты делают руками. Примеры: `SCADA1_192.168.0.100\*.PNG` (XP SP3, EN), `NEVSKA03_192.168.16.68\*.PNG` (XP, RU, поверх полноэкранная SCADA InTouch), `DESKTOP-8IF9F5V_10.0.0.38\*.png` (Win10, RU).
- Каждый скрин — **весь экран**, на нём:
  1. целевое окно (слева/по центру, полностью видно);
  2. справа окно сведений о системе (XP: «Свойства системы», 7/10: «Система»), чтобы было видно имя ПК и версию ОС;
  3. дата: на XP — всплывающая подсказка над часами в трее, на 7/10 дата видна в трее (подсказку всё равно вызываем).

## 2. Цель и границы

- Отдельная программа `screens.exe` на **чистом C** (без C++), только WinAPI, без внешних DLL — только системные.
- Делает только скриншоты. Сбор данных остаётся в `collect_audit.cmd`, в нём добавляется лишь вызов утилиты.
- ОС: Windows XP SP2/SP3 x86, Windows 7 x86/x64, Windows 10 x64. Желательно: Server 2003/2008/2012/2016, Windows 11. Языки интерфейса: RU и EN.
- Никогда не зависать: каждый шаг с таймаутом, общий сторожевой таймер, при сбое — пропустить скрин, записать в журнал, закрыть открытые окна, идти дальше.

Имена файлов — как в примере SCADA1, задаются одной таблицей в коде. Формат PNG, файлы кладутся в корень папки `OUT`.

## 4. Устройство программы

```
screens/
  PLAN.md
  build.cmd            сборка x86 и x64 (msbuild, набор v141_xp)
  screens.vcxproj      проект Visual Studio (Win32 и x64)
  screens.manifest     + screens.rc (манифест, иконка не нужна)
  src/main.c           аргументы, проверки, цикл по сценариям, сторожевой таймер
  src/log.c/.h         журнал в UTF-8 с BOM
  src/osinfo.c/.h      версия ОС (RtlGetVersion), права администратора, интерактивный стол
  src/capture.c/.h     снимок экрана и запись PNG
  src/wnd.c/.h         запуск процессов, поиск новых окон, раскладка, передний план, закрытие
  src/remote.c/.h      буфер в чужом процессе (VirtualAllocEx/WriteProcessMemory/ReadProcessMemory)
  src/mmc.c/.h         навигация по дереву MMC (SysTreeView32) и списку (SysListView32)
  src/names.c/.h       словарь названий узлов RU/EN
  src/scenarios.c/.h   таблица сценариев
  src/console.c/.h     окно cmd: размер буфера, ввод команд через помощника (screens.exe /conhelper:PID)
  src/tray.c           подсказка с датой у часов, «шарики» уведомлений
  src/scroll.c/.h      постраничная съёмка длинного списка (колесо мыши)
  third_party/stb_image_write.h   (public domain, кодирование PNG)
  vmtest/              агент для ВМ и скрипты тестового цикла (раздел 8)
bin/ (результат сборки, кладётся рядом с collect_audit.cmd)
  screens_x86.exe
  screens_x64.exe
```

### Командная строка
```
screens.exe <папка_результатов> [/only:имя1,имя2] [/list] [/keep] [/dump] [/timeout:сек] [/allmonitors]
```
- `/only` — снять только указанные сценарии; `/list` — вывести список сценариев.
- `/keep` — не закрывать окна (отладка).
- `/dump` — записать в журнал дерево окон и дерево MMC (для удалённой диагностики на чужом языке/ОС).
- `/allmonitors` — снимать весь виртуальный экран (по умолчанию — основной монитор).
- `/conhelper:<PID> …` — служебный: помощник для окна cmd (`sync_time`), запускает его сама утилита.
- Коды возврата: 0 — все скрины сделаны; 1 — часть не удалась; 2 — снимать нельзя (нет интерактивного стола, экран заблокирован и т. п.).
- Журнал: `<папка>\_журнал_скриншотов.txt`. Отдельный файл, потому что `_журнал_сбора.txt` пишется в 1251 и конвертируется в конце cmd.

## 5. Ключевые технические решения

**Сборка**
- На домашнем ПК стоит Visual Studio 2026 с C++. Её собственный набор инструментов **не годится**: начиная с VS 2019 штатные наборы не делают exe для XP (рантайм и линкер рассчитаны на Vista/7+).
- **Основной вариант — набор `v141_xp`** (компилятор VS 2017 + Windows 7.1A SDK). Ставится из того же Visual Studio Installer → «Отдельные компоненты» → «C++ Windows XP Support for VS 2017 (v141) tools [Deprecated]» и «MSVC v141 — VS 2017 C++ x64/x86 build tools». Ничего со сторонних сайтов не нужно. Что он есть именно в установщике VS 2026, не проверено — первым делом посмотреть поиском «XP» на вкладке «Отдельные компоненты».
- Если в VS 2026 этого компонента нет: поставить рядом бесплатные **Build Tools for Visual Studio 2022** (с сайта Microsoft) с тем же компонентом. Если и это не подходит — портативный MinGW-w64 WinLibs с рантаймом msvcrt (сторонняя сборка, только распаковать архив).
- Сборка из командной строки: проект `screens.vcxproj` с `PlatformToolset=v141_xp`, конфигурации Win32 и x64, собирать `msbuild` из `build.cmd` (путь к msbuild искать через `vswhere`). Настройки: Unicode, `/MT` (статический рантайм, без VC-redist на объекте), `_WIN32_WINNT=0x0501`, `WINVER=0x0501`, компоновщик `/SUBSYSTEM:CONSOLE,5.01` (x86) и `5.02` (x64). Оба exe собирать одним набором `v141_xp`.
- Код писать на C, который понимает компилятор VS 2017 (файлы `.c`, компилировать как C: `/TC`). VLA и `_Complex` не использовать.
- **Обязательно** проверить версию подсистемы в заголовке exe (`dumpbin /headers` → «subsystem version» 5.01 / 5.02). Иначе XP пишет «не является приложением Win32».
- После сборки проверять импорты: `dumpbin /imports`. Ничего новее XP SP2 в статическом импорте быть не должно.
- Всё, чего нет в XP (`SetProcessDPIAware`, `Wow64DisableWow64FsRedirection` и т. п.), — только через `GetProcAddress`.
- Манифест: `asInvoker` (cmd уже запущен от администратора, двойного UAC не нужно), `dpiAware=true` (иначе на Win10 с масштабом 125–150 % снимок обрежется), supportedOS для Vista…10.
- Если в итоге используется MinGW: флаги `-std=c99 -O2 -municode -DUNICODE -D_UNICODE -D_WIN32_WINNT=0x0501 -static -static-libgcc -s -Wl,--subsystem,console:5.01`, проверка импортов `objdump -p`.

**Две сборки, x86 и x64.** Чтобы читать TreeView/ListView чужого процесса, структуры `TVITEM`/`LVITEM` должны совпадать по разрядности с mmc.exe. На x64-системе mmc 64-битный. cmd выбирает exe по `PROCESSOR_ARCHITECTURE`: `collect_audit.cmd` уже перезапускает себя в 64-битном cmd, поэтому там будет `AMD64`.

**Проверка, можно ли снимать.** Станция окон процесса `WinSta0`, `OpenInputDesktop` успешен, имя стола `Default` (на заблокированном экране — `Winlogon`). Сессию 0 как признак не использовать: на XP консоль работает в сессии 0. Если снимать нельзя — код 2, запись в журнал, выход.

**Поиск открытых окон.** До запуска запомнить список видимых окон верхнего уровня, после запуска ждать **новое** видимое окно (с фильтром по классу: `MMCMainFrame`, `#32770`, `CabinetWClass`, `ConsoleWindowClass`). Так не нужно знать заголовки на разных языках, и это работает для окон панели управления, которые принадлежат explorer.exe, а не запущенному процессу. Все открытые окна и PID складывать в список для закрытия.

**Навигация в MMC (gpedit, lusrmgr).**
- Найти внутри `MMCMainFrame` дочерний `SysTreeView32` (обход `EnumChildWindows`).
- Обход дерева: `TVM_GETNEXTITEM` (`TVGN_ROOT`/`TVGN_CHILD`/`TVGN_NEXT`). Текст — `TVM_GETITEMW` с буфером, выделенным в процессе mmc.
- Сравнение с названиями из словаря RU/EN: без учёта регистра, `ё`→`е`, по точному совпадению или по началу строки.
- Раскрытие: MMC заполняет узлы лениво по `TVN_ITEMEXPANDING`, а `TVM_EXPAND` это уведомление не шлёт. Поэтому: `TVM_SELECTITEM(TVGN_CARET)` → `PostMessage(WM_KEYDOWN, VK_RIGHT)` дереву → ждать, пока появятся дети (до 5 с). Выделение конечного узла через `TVM_SELECTITEM` (MMC получает `TVN_SELCHANGED` и показывает правую панель).
- Если узел не найден — записать в журнал имена всех детей этого уровня (чтобы дополнить словарь) и пропустить сценарий.
- Запасной путь, если сообщения не сработают на какой-то ОС: MSAA (`AccessibleObjectFromWindow` + `IAccessible` через vtbl из C, есть на XP) — найти элемент и `accSelect`.

**Свойства группы (lusrmgr).**
- Имя группы по SID: `LookupAccountSidW` для S-1-5-32-544 / S-1-5-32-545 (даёт локализованное «Администраторы»/«Administrators»).
- В правой панели `SysListView32`: `LVM_GETITEMCOUNT`, `LVM_GETITEMTEXTW` (удалённый буфер), найти строку, выделить `LVM_SETITEMSTATE`, `LVM_ENSUREVISIBLE`, затем `PostMessage(WM_KEYDOWN, VK_RETURN)` — откроется диалог свойств. Ждать новый `#32770` того же PID. Запасной путь — меню «Действие → Свойства» через `WM_COMMAND`.

**Вкладки диалогов** («Время Интернета» в timedate.cpl, «Общие» в sysdm.cpl): после открытия переключать через `PSM_SETCURSEL` по индексу на окне property sheet. Это не требует буферов и не зависит от языка. Параметр командной строки `,,N` использовать, но не полагаться только на него. В домене вкладки «Время Интернета» нет — тогда снимать без неё.

**Раскладка и передний план.**
- Рабочая область — `SystemParametersInfo(SPI_GETWORKAREA)`. Окно сведений о системе прижать вправо, целевое окно — слева, размеры пропорционально экрану. На 800×600 допускается перекрытие, но целевое окно и диалог свойств должны быть видны полностью и лежать сверху.
- Поверх полноэкранной SCADA (InTouch бывает TOPMOST): на время снимка `SetWindowPos(HWND_TOPMOST)`, после — `HWND_NOTOPMOST`.
- `SetForegroundWindow` обходить через `AllowSetForegroundWindow(ASFW_ANY)` + `AttachThreadInput` с потоком текущего переднего окна.

**Дата у часов.** `Shell_TrayWnd` → `TrayNotifyWnd` → `TrayClockWClass`, курсор (`SetCursorPos`) в центр часов, ждать видимый `tooltips_class32` до 3 с, потом снимок. Курсор после вернуть на место. Если часов/подсказки нет — снимать без неё, записать в журнал.

**Снимок.** `GetDC(NULL)` → `CreateDIBSection` 32 бит → `BitBlt` с флагом **`CAPTUREBLT`** (иначе на XP не попадут слоистые окна, в том числе подсказка с датой). BGRA → RGB, запись `stbi_write_png`. Перед снимком пауза ~500 мс на перерисовку.

**Закрытие.** `WM_CLOSE` всем открытым окнам в обратном порядке. Если появился вопрос о сохранении консоли — ответить «Нет» (`IDNO`). Если mmc/cmd не закрылся за 5 с — `TerminateProcess` по нашему PID. Процесс explorer.exe никогда не завершать, окна панели управления закрывать только через `WM_CLOSE`.

**Сторожевой таймер.** Отдельный поток: если вся работа идёт дольше лимита (по умолчанию 5 мин), закрыть всё открытое, записать в журнал, выйти с кодом 1.

## 6. Встраивание в collect_audit.cmd

- Новый раздел `:collect_screens`, вызывается после `:collect_logs`, до `:run_network`.
- Выбор exe: `screens_x64.exe`, если `PROCESSOR_ARCHITECTURE=AMD64`, иначе `screens_x86.exe`. Искать рядом со скриптом (`%~dp0`). Если exe нет — строка в журнале и дальше.
- Новый ключ `/noscreens`. Запуск: `"%SCR_EXE%" "%OUT%"`, код возврата в `_журнал_сбора.txt` через `:log`.
- Файл сохранять в **Windows-1251 с CRLF** (как сейчас), новые строки комментариев — по-русски, в стиле файла. Шапку скрипта (описание ключей и состава папки) дополнить.
- Позже (не в этом этапе): научить `make_report_ib.cmd` брать `Ustanovlennoe_PO.png` вместо ручного скрина «Установленное ПО ИМЯ_IP».

   - Win10 20H2+ (сборка ≥ 19042) и 11: «Система» открывает Параметры (версия ОС ниже края окна) → сразу «Свойства системы»; `rundll32/control sysdm.cpl` на Win10 22H2 **молча ничего не открывают** → на 6.x+ `SystemPropertiesComputerName.exe`; без прав администратора он даёт ошибку 740 → запасной вариант «Система»/Параметры (там тоже видно имя ПК);

   - сторожевой таймер поднимает флаг прерывания (длинные шаги выходят), закрывает окна, курсор возвращает последним; проверено `/timeout:4` на Win10 — оба окна закрыты, код 1;
   - тестовый цикл запускает `run.cmd` с повышением прав, как у пользователя: Win7 — «Пуск» → `cmd` → Ctrl+Shift+Enter → UAC (Shift+Tab, Enter); Win10 — Win+R `powershell -w hidden -c "saps cmd -Verb RunAs -Args '/c …'"` (Ctrl+Shift+Enter в «Выполнить» повышает через раз; поле «Выполнить» ≤ 259 символов — длинная строка обрезается и молча не работает), UAC ловится по снимку экрана гостя (серое тело диалога в центре + затемнённый фон), затем ←, Enter. `net use \\vboxsrv\screens <nul` нужен на Win10/XP, а в повышенном cmd Win7 он висит — там не делается. Новая общая папка видна в сеансе пользователя через 1–2 мин → в госте цикл ожидания до 90 с, на хосте ждём `started.txt` 150 с.
   - Итог: `vmtest\итог_этап2` — 6 ВМ, код 0, все окна закрыты; сторожевой таймер (`/timeout:4`) — код 1, окна закрыты.

   **Постраничный список ПО (06.11.2026, по запросу).** Если список не помещается — несколько снимков `Установленное ПО_1.png`, `_2`, … (суффикс есть всегда), не больше 10 (`/pages:N`). Листается только список ПО. Модуль `scroll.c`, способ один для всех ОС (XP ARP и «Программы и компоненты» — DirectUI, обычной полосы прокрутки нет):
   - щелчок колеса (SendInput, курсор над списком) → изменившаяся область кадра = видимая часть списка V, сдвиг картинки = шаг щелчка p; затем до конца списка, суммируя измеренные сдвиги = длина прокрутки S; обратно наверх;
   - страниц n = 1 + ⌈S / (V − перекрытие)⌉, шаг = S / (n − 1): у всех страниц одинаковое перекрытие, последняя — ровно конец списка; к цели — частями ≤ 60% V, каждая измеряется;
   - сдвиг измеряется сравнением хэшей строк пикселей по **доле** совпавших строк (≥ 90%), не по их числу: строки «Screens Test Program NN» отличаются только цифрами, и ложный сдвиг на кратное высоте пункта по числу совпадений выигрывал — длина занижалась втрое;
   - щелчки колеса — с паузой 60 мс: при 25 мс XP терял часть щелчков;
   - найдено попутно: `wnd_unraise` снимал «поверх всех» в обратном порядке — окно сведений вылезало поверх целевого (на 800×600 закрывало часть списка);
   - `/dump` пишет в журнал измерения, а при неудачном сравнении — пары кадров `_прокрутка_N_до/после.png`;
   - тест: 50 фиктивных программ (`vmtest\prep_fake_apps.cmd`, `vm_test.ps1 -Prep`) на трёх XP: 1024×768 — 2 страницы, 800×600 — 3 страницы.
   - Win7 и Win10 без фиктивных программ (06.11.2026): одна страница `_1`, код 0. На Win10 список, который помещается по высоте, но не по ширине, колесо прокручивает **по горизонтали** — сдвиг «не измерить», снимается одна страница (итог верный, список возвращается влево). Однажды на Win10 после этого в списке оказался выделен пункт (внизу издатель вместо «Установлено программ: N»); в первом прогоне — нет. Разобрать на этапе 8.
3. **Сценарий `sync_time`** (cmd с эхом команды; на XP ещё timedate.cpl с переключением вкладки).
   **Сделано 06.11.2026.** Модуль `console.c` (был `con.c`). Как устроено и что выяснилось:
   - cmd — обычный интерактивный `cmd.exe` в **новой консоли** (`CREATE_NEW_CONSOLE`, иначе он сядет в консоль screens.exe), папка — `%USERPROFILE%`: в окне шапка «Microsoft Windows…» и приглашение, как при запуске через «Выполнить». Команды **вводятся «с клавиатуры»** (`WriteConsoleInputW`, пары «нажата/отпущена», символ в `uChar`), поэтому видно «приглашение>команда» и вывод — как на ручных примерах. Пакетный файл с `echo on` дал бы похожее, но без шапки.
   - С чужой консолью работает **помощник** — та же screens.exe с ключом `/conhelper:<PID>` (`DETACHED_PROCESS`, затем `AttachConsole`): основной процесс сам консольный (окно collect_audit.cmd) и не может прицепиться к другой консоли, не потеряв свою. Помощник ждёт приглашения, вводит команды по одной, пишет текст консоли в `%TEMP%\screens_con_<PID>.txt` (UTF-16), основной процесс переносит его в журнал и удаляет файл. Код возврата помощника: 0 — всё выполнено, 11 — нет AttachConsole, 13 — команда не завершилась за 30 с.
   - команда выполнена, когда: ввод разобран (`GetNumberOfConsoleInputEvents` = 0), у cmd **нет дочерних процессов** (Toolhelp; `conhost.exe` не считается — на Win8+ cmd сам запускает его и он живёт всё время) и курсор стоит 800 мс. Каждая команда — около 1 с.
   - **ширину консоли задавать при запуске**: на XP/7 консоль при сужении буфера не переносит, а обрезает уже выведенные строки (шапка Win7 становилась «All rights reserv»); Win10 переносит сам. Размер символа и рамку берём у собственной консоли (окно collect_audit.cmd — тот же cmd с теми же настройками): клиентская часть / число столбцов. `STARTF_USECOUNTCHARS` (буфер) **вместе с** `STARTF_USESIZE` (окно в пикселях; консоль делит их на размер символа) и `STARTF_USEPOSITION`: с одним буфером окно остаётся 80 столбцов, и консоль расширяет буфер до ширины окна (проверено на Win7). После запуска помощник досчитывает высоту; на XP после команд окно уменьшается по содержимому — под ним встаёт «Дата и время».
   - шрифт: XP/7 — растровый 8×12, Win10 — 8×16. Рядом с панелью «Система» Win7 (700 px) cmd получает 60 столбцов: строки вывода w32tm переносятся, ничего не теряется.
   - XP «Дата и время»: вкладку «Время Интернета» XP добавляет **через ~300 мс после появления окна** (в первый раз вкладок было 2 — приняли за домен). Ждём до 3 с, пока `TCM_GETITEMCOUNT` (окно вкладок — `PSM_GETTABCONTROL`) станет ≥ 3, затем `PSM_SETCURSEL` 2. Меньше трёх (домен) — окно закрываем и снимаем без него; с `/dump` перед закрытием снимок `_дата_и_время.png`. Нет окна вкладок (например, сообщение о нехватке прав) — тоже закрываем.
   - раскладка XP: cmd слева сверху по содержимому, «Дата и время» под ним правым краем к «Свойствам системы» (как в SCADA1/NEVSKA03); 6.x+: cmd слева на всю высоту.
   - на стенде служба W32Time на Win7/Win10 остановлена (рабочая группа) — w32tm честно пишет «Служба не запущена (0x80070426)». Службы утилита не запускает и настроек не меняет. На XP служба работает, сервер time.windows.com, синхронизация — «узел недоступен» (сети нет).
   - Риски: Win11 с Windows Terminal по умолчанию — окно cmd будет не `ConsoleWindowClass` (не найдём за 15 с, сценарий не удастся; разобрать на этапе 6). Антивирус может не любить `AttachConsole`/`WriteConsoleInput` в чужую консоль (раздел 9).
   - на снимках за окнами виден консольный `run.cmd` (в работе — окно collect_audit.cmd): утилита его не трогает.
   - Итог: `vmtest\итог_этап3` — 6 ВМ, `/only:Ustanovlennoe_PO,sync_time /dump`, код 0, все окна закрыты; доп. проверка — XP SP3 при 800×600 (cmd и «Дата и время» видны целиком, у «Свойств системы» перекрыт заголовок, сведения видны). Серию по ВМ запускает `vmtest\vm_series.ps1`.

## 8. Тестирование

### Тестовые ВМ на домашнем ПК
6 виртуальных машин: Windows XP SP2 и SP3 в английской и русской версиях (точный набор уточнить), Windows 7 Корпоративная, Windows 10 Pro. Тестирую сам через консольную утилиту гипервизора:

- **Определить гипервизор** и его CLI: VirtualBox — `VBoxManage`, VMware Workstation — `vmrun`, Hyper-V — PowerShell (`Start-VM` и т. п.; XP под Hyper-V почти без интеграции, хуже всего подходит).
- **Управление ВМ:** запуск/остановка, снимки состояния, снимок экрана гостя на хосте (`VBoxManage controlvm <vm> screenshotpng`, `vmrun captureScreen`). Эти PNG я смотрю сам, так что вижу, что происходит в госте.
- **Главная тонкость:** утилите нужен интерактивный рабочий стол вошедшего пользователя. Процесс, запущенный через `guestcontrol`/`runProgramInGuest`, может оказаться в другой сессии или на невидимом столе. Поэтому основной способ запуска — **агент в госте** (`vmtest/agent.cmd`):
  - общая папка хост↔гость (например `\\vboxsvr\share` или `Z:`);
  - в автозагрузке пользователя гостя маленький `agent.cmd`: раз в 2–3 с проверяет, появился ли в общей папке `run.cmd`, переименовывает его и запускает в интерактивной сессии, вывод и код возврата пишет обратно в общую папку;
  - автовход пользователя-администратора в гостях, чтобы после запуска ВМ агент поднимался сам.
  - Запасной вариант — `vmrun -interactive runProgramInGuest` (VMware) или `VBoxManage guestcontrol run`, если проверка покажет, что окна появляются на видимом столе.
- **Цикл теста:** восстановить снимок «чистое состояние» → запустить ВМ → дождаться агента → положить `screens_*.exe` и `run.cmd` в общую папку → дождаться результата → забрать PNG и журнал, посмотреть их и снимок экрана гостя → при необходимости поправить код и повторить.
- **Перед любым откатом снимка или удалением состояния ВМ спрашивать пользователя.** Восстанавливать только снимки, созданные для тестов этой утилиты.
- Если CLI гипервизора недоступен — запасной вариант через управление рабочим столом хоста (computer use): смотреть окно ВМ и кликать в нём. Медленнее, использовать только для разовых проверок.

### Общее
- Для разбора проблем — `/dump` и снимок экрана гостя.
- Матрица: XP SP2 RU/EN, XP SP3 RU/EN, 7, 10 x64; рабочая группа и домен (если есть); 800×600, 1024×768, 1280×1024, 1920×1080; масштаб 100 % и 125–150 % (Win10); поверх открыта полноэкранная программа.

## 9. Риски

- Антивирус (на объектах Kaspersky) может сработать на запись в память чужого процесса, эмуляцию ввода (в том числе ввод в чужую консоль через `AttachConsole` + `WriteConsoleInput`, сценарий `sync_time`), запуск собственной копии с ключом `/conhelper` и снимок экрана. Возможно, понадобится исключение или подпись exe.
- Win11 с Windows Terminal как терминалом по умолчанию: cmd откроется не в `ConsoleWindowClass`.
- Названия узлов в локализациях, которых нет в словаре. Лечится `/dump` и дополнением `names.c`.
- Медленные старые машины: заполнение списка программ на XP и запуск mmc. Таймауты — параметром.
- Компонент `v141_xp` помечен как устаревший и может пропасть из будущих версий установщика — тогда Build Tools 2022 или MinGW.

## 10. Решения (06.11.2026)

1. **Компилятор.** В VS 2026 (18.x) компонента `Microsoft.VisualStudio.Component.WinXP` нет (в каталоге установщика только v141 без XP). Ставим **Build Tools for Visual Studio 2022** с компонентами `Microsoft.VisualStudio.Component.WinXP` и `Microsoft.VisualStudio.Component.VC.v141.x86.x64`. `build.cmd` ищет установку через `vswhere -requires Microsoft.VisualStudio.Component.WinXP`. Для пробы без XP: `build.cmd /toolset:v145` (результат в `obj\v145\`, не в `bin\`).
2. **ВМ.** VirtualBox 7.2.6, 6 гостей со снимком `clean` (см. память о стенде). Агент в госте **не делаем**: запуск нажатиями клавиш (`VBoxManage controlvm keyboardputscancode/keyboardputstring`, Win+R `\\vboxsvr\screens\run.cmd`), временная общая папка `screens` = `vmtest\share`. Скрипт цикла — `vmtest\vm_test.ps1`. Откатываться к `clean` после прогонов разрешено.
3. **Имена файлов** — как в NEVSKA03: `Установленное ПО.png`, `Аудит.png`, `Политика паролей.png`, `Политика блокировки.png`, `sync_time.png`, `user_list.png`, `user_list_admin.png`, `user_list_users.png`. Имена для `/only` — латинские (`Ustanovlennoe_PO`, `audit_base`, …, как в таблице раздела 3).
4. **Область снимка** — по умолчанию **весь виртуальный экран** (все мониторы). Ключ `/primary` — только основной монитор (`/allmonitors` оставлен как синоним умолчания).
