# screens.exe — утилита скриншотов для collect_audit.cmd

## 1. Контекст

- Утилита — часть сбора данных для аудита ИБ. Сам сбор делает `collect_audit.cmd` (лежит **вне этого репозитория**, в родительской папке `C:\dev\repos\collect_data`; cmd, Windows-1251, CRLF, ~2000 строк). Он создаёт папку `%ROOT%\%COMPUTERNAME%_%IP%` (переменная `OUT`), вызывает разделы `:collect_*`, затем `:convert_utf8`. Отчёт строят `make_md.ps1` и `make_report_ib.cmd` (там же).
- Раньше скриншоты делали руками. Примеры: `SCADA1_192.168.0.100\*.PNG` (XP SP3 EN), `NEVSKA03_192.168.16.68\*.PNG` (XP RU, поверх полноэкранная SCADA InTouch), `DESKTOP-8IF9F5V_10.0.0.38\*.png` (Win10 RU) — в родительской папке.
- Каждый снимок — **весь экран**, на нём:
  1. целевое окно (слева, полностью видно);
  2. справа окно сведений о системе (XP — «Свойства системы», 7/10 — «Система» или «Свойства системы»): видно имя ПК и версию ОС;
  3. дата: всплывающая подсказка над часами в трее (вызывается на всех ОС).

## 2. Требования и границы

- **Чистый C** (без C++), только WinAPI и системные DLL. Делает только скриншоты; сбор данных остаётся в `collect_audit.cmd`, туда добавляется лишь вызов утилиты.
- ОС: Windows XP SP2/SP3 x86, XP x64 / Server 2003, Windows 7 x86/x64, Windows 10 x64. Желательно: Server 2008–2016, Windows 11. Языки интерфейса RU и EN.
- **Никогда не зависать**: у каждого шага таймаут, общий сторожевой таймер; при сбое — пропустить снимок, записать в журнал, закрыть открытые окна, идти дальше.
- Службы не запускать, настроек системы не менять.

**Окно сведений о системе** открывается один раз (`scen_sysinfo`) и остаётся для всех снимков:
- XP/2003: `rundll32 shell32.dll,Control_RunDLL sysdm.cpl,,0`, вкладка «Общие».
- Vista…Win10 до 20H2: `control /name Microsoft.System`; если открылись Параметры (`ApplicationFrameWindow`) — закрыть и взять «Свойства системы».
- Win10 20H2+ (сборка ≥ 19042) и Win11: сразу «Свойства системы» — `SystemPropertiesComputerName.exe` (`rundll32/control sysdm.cpl` на Win10 22H2 молча ничего не открывают). Без прав администратора он даёт ошибку 740 → запасной вариант «Система»/Параметры (там тоже видно имя ПК).

**Нет оснастки** (Home-редакции без gpedit/lusrmgr), план: gpedit → `secpol.msc` → иначе окно cmd с `net accounts` / `auditpol /get /category:*` / `net user` / `net localgroup <имя>`; в журнал — что использован запасной вариант.

## 5. Командная строка

```
screens.exe <папка_результатов> [/only:имя1,имя2] [/list] [/keep] [/dump] [/timeout:сек] [/wait:сек] [/pages:N] [/primary]
```
- `/only:...` — только указанные сценарии; `/list` — список сценариев.
- `/keep` — не закрывать окна (отладка).
- `/dump` — подробности в журнал (измерения прокрутки, дерево MMC), диагностические кадры `_прокрутка_N_до/после.png`, `_дата_и_время.png`.
- `/timeout:N` — общий лимит работы, с (по умолчанию 300). `/wait:N` — ожидание заполнения окна, например списка программ (45). `/pages:N` — не больше N страниц списка ПО (10, максимум 100).
- По умолчанию снимается **весь виртуальный экран** (все мониторы); `/primary` — только основной монитор; `/allmonitors` — синоним умолчания.
- `/conhelper:<PID> …` — служебный запуск помощника для окна cmd, утилита запускает его сама.
- Коды возврата: 0 — все выбранные сценарии сняты; 1 — часть не удалась (нереализованные сценарии тоже считаются неудачей, поэтому без `/only` сейчас всегда 1; сторожевой таймер — тоже 1); 2 — снимать нельзя (нет интерактивного стола, экран заблокирован) или ошибка аргументов/папки.
- Журнал: `<папка>\_журнал_скриншотов.txt` (UTF-8 с BOM, дописывается). Отдельный файл, потому что `_журнал_сбора.txt` пишется в 1251 и конвертируется в конце cmd. Тексты строк журнала разбирает `vmtest\make_summary.ps1` (`ОС:`, `Сборка утилиты:`, `Экран:`, `подсказка появилась через`, `Спрятано всплывающих уведомлений`, `СТОРОЖ`, `закрыто`, `Завершено`, `ОШИБКА`) — не менять их без правки скрипта.

## 6. Сборка

- `build.cmd` — набор **`v141_xp`** (компилятор VS 2017 + Windows 7.1A SDK) из **Build Tools for Visual Studio 2022** с компонентами `Microsoft.VisualStudio.Component.WinXP` и `Microsoft.VisualStudio.Component.VC.v141.x86.x64`. В VS 2026 компонента XP нет; штатные наборы VS 2019+ не делают exe для XP. Установка ищется через `vswhere -requires Microsoft.VisualStudio.Component.WinXP`.
- `build.cmd /toolset:v145` — пробная сборка новым набором (результат в `obj\v145\`, не для XP); `/nocheck` — без проверки dumpbin.
- Настройки: компиляция как C (`/TC`), Unicode, `/MT` (статический рантайм), `/W4` без предупреждений, `/utf-8`, `_WIN32_WINNT=0x0501`, подсистема `5.01` (x86) / `5.02` (x64).
- **После сборки обязательно**: `build.cmd` проверяет версию подсистемы (иначе XP пишет «не является приложением Win32») и печатает импорты — только KERNEL32, USER32, GDI32, ADVAPI32. Импорты сверяются с настоящими DLL XP SP2 скриптом `vmtest\check_imports.ps1` (DLL в `vmtest\xpdlls\`, их нет в git — файлы Microsoft, распаковываются из ISO).
- Всё, чего нет в XP (`SetProcessDpiAwareness*`, `SetProcessDPIAware` и т. п.), — только через `GetProcAddress`.
- Две сборки x86/x64: структуры `TVITEM`/`LVITEM` для чужого mmc.exe должны совпадать с ним по разрядности. exe выбирается по `PROCESSOR_ARCHITECTURE` (`collect_audit.cmd` перезапускает себя в 64-битном cmd → `AMD64`).
- C, который понимает компилятор VS 2017: объявления в середине блока и `for (int i…)` можно; VLA, `_Complex` и неконстантные инициализаторы структур (`C4204` на `/W4`) — нельзя.

## 7. Правила кода (ревью 07.11.2026)

- **Без `goto`**: функции разбиваются на небольшие `static`-функции, освобождение ресурсов в одном месте.
- **Без магических чисел**: каждое неочевидное число — `#define` с комментарием (таймауты, пороги, размеры буферов, маски). Общие — в `src/common.h` (`PATH_BUFFER_CCH`, `TEXT_BUFFER_CCH`, `MESSAGE_BUFFER_CCH`, `CLASS_NAME_CCH`, `PIXEL_RGB_MASK`, `PERCENT_BASE`, `MS_PER_SECOND`, `DECIMAL_BASE`, `TERMINATED_EXIT_CODE`, `WARN_DEPRECATED`), остальные — в начале своего `.c`. Коды предупреждений MSVC — тоже именами: `#define WARN_CONVERSION_DATA_LOSS 4244 // C4244: ...`, затем `#pragma warning(disable: WARN_...)` (MSVC 14.16 подставляет макросы в `disable:` и `suppress:`, проверено). Литералами остаются только 0/1/2, `/ 2` для середины и именованные таблицы данных.
- **Имена полными словами**: без сокращений и однобуквенных (`ptr`, а не `p`; `screen_dc`/`memory_dc`, а не `scr`/`mem`) — в переменных, полях, глобальных и static-функциях. Допустимы `i`/`j` в счётчиках циклов и `x`/`y` как координаты. Публичные функции модулей носят префикс модуля (`cap_`, `wnd_`, `con_`, `log_`, `os_`, `scen_`, `scroll_`, `buffer_`), типы — ЗАГЛАВНЫМИ (`CAP_FRAME`, `WND_SET`, `BUFFER`).
- **Стиль Allman**: открывающая скобка на новой строке везде (функции, блоки, `struct`, `switch`, инициализаторы массивов).
- Тело из одной короткой инструкции — на той же строке без скобок: `if (count == 0) return FALSE;`. Длиннее 120 символов — на отдельные строки в скобках. Строки кода — не длиннее 120 символов (длинные строковые литералы делить склейкой `L"..." L"..."`).
- **Пустые строки** между логическими шагами: объявления / проверки / действия.
- **Комментарии `//`**, без украшений (`// помощник (отдельный процесс)`, а не `/* ===== ... ===== */`). Комментарии и сообщения журнала — по-русски.
- **Память — через `BUFFER`** (`src/buffer.h`: `void *data; size_t size;`, `buffer_init`, `buffer_init_array` с проверкой переполнения `count * size`, `buffer_destroy`; возвращают `BUFFER_OK`/`BUFFER_ERROR`). Пустой буфер `{ 0 }` можно освобождать всегда. Большие структуры (`WND_SET`) — не на стеке.
- Строки форматировать через `format_text` (всегда завершает нулём).
- Прежде чем браться за неясную задачу — задать вопросы и продолжать после ответов.

## 8. Технические решения и проверенные факты

**Можно ли снимать.** Станция окон `WinSta0`, `OpenInputDesktop` успешен, входной стол и стол потока — `Default` (заблокированный экран — `Winlogon`). Сессию 0 как признак не использовать: на XP консоль работает в сессии 0. Нельзя — код 2.

**DPI.** `os_set_dpi_aware()` — до любых `GetSystemMetrics`, иначе на Win10 с масштабом > 100 % размеры экрана занижены. Размеры раскладки заданы для 96 DPI и масштабируются.

**Поиск окон.** До запуска запомнить видимые окна верхнего уровня (`WND_SET`), после — ждать **новое** видимое окно с фильтром по классу (`#32770`, `CabinetWClass`, `ConsoleWindowClass`, `MMCMainFrame`) или любое окно приложения (с заголовком, ≥ 150×100). Заголовки на разных языках знать не нужно; работает и для окон панели управления, которые принадлежат explorer.exe. Все открытые окна и PID — в список для закрытия.
- XP: «Установка и удаление программ» — `NativeHWNDHost` в процессе rundll32 (можно завершать), «Свойства системы» — `#32770` 419×504. 7/10: окна панели управления — `CabinetWClass` в explorer.exe (только `WM_CLOSE`, explorer никогда не завершать).

**Готовность окна.** Картинка не меняется 2,5 с (изменения меньше 1/2000 площади, не меньше 64 пикселей, не считаются — мигающая каретка) **и** процесс окна за это время < 10 % ЦП и < 40 операций ввода-вывода. Лимит — `/wait`. XP долго считает размеры программ.

**Раскладка.** Рабочая область — `SPI_GETWORKAREA`. Диалог сведений — своего размера, справа внизу. Панель «Система» Win7 — 45 % ширины, но 700…900 (уже 700 имя ПК обрезается ссылкой «Изменить параметры»), справа сверху до полосы 48 px над часами (иначе имя ПК под подсказкой). Целевое окно — слева на оставшееся место, ширина ≥ 520 и ≥ 50 % (при нехватке перекрывает левую колонку «Системы»). На 800×600 допускается перекрытие.

**Передний план.** На время снимка `HWND_TOPMOST` (поверх полноэкранной SCADA), после — `HWND_NOTOPMOST` **в прямом порядке** (в обратном окно сведений вылезало поверх целевого). `SetForegroundWindow` — через `AllowSetForegroundWindow(ASFW_ANY)` + `AttachThreadInput`.

**Дата у часов** (`tray.c`). `Shell_TrayWnd` → `TrayNotifyWnd` → `TrayClockWClass`; на Win11 часы не окно — правый край панели. Наведение — только `SendInput` (на Win10 `SetCursorPos` подсказку не вызывает), подход в несколько шагов, раз в секунду повтор; ждать до 3 с. Подсказка: XP/10 — `tooltips_class32`, Win7 — `ClockTooltipWindow`; признак — окно, ставшее видимым после наведения, рядом с часами (≤ 400 px), не `TTS_BALLOON`. Курсор потом вернуть.
**«Шарики» уведомлений** XP закрывают трей: прятать `SW_HIDE` (не `TTM_POP` — он сразу показывает следующий из очереди), вместе с окнами тени `SysShadow`, затем `RedrawWindow` области; повторно — прямо перед снимком.

**Снимок.** `GetDC(NULL)` → `CreateDIBSection` 32 бит → `BitBlt` с **`CAPTUREBLT`** (иначе на XP не попадут слоистые окна, в том числе подсказка), без него — запасной вариант. BGRA → RGB, `stbi_write_png_to_func` во временный файл и переименование. Перед снимком 500 мс на перерисовку.

**Постраничный список ПО** (`scroll.c`, один способ для всех ОС: XP ARP и «Программы и компоненты» — DirectUI без обычной полосы прокрутки):
- щелчок колеса (`SendInput`, курсор над списком) → изменившаяся область кадра = видимая часть V, сдвиг картинки = шаг щелчка p; до конца списка, суммируя измеренные сдвиги = длина прокрутки S; обратно наверх;
- страниц n = 1 + ⌈S / (V − перекрытие)⌉, шаг = S / (n − 1): одинаковое перекрытие, последняя — ровно конец; к цели частями ≤ 60 % V, каждая измеряется;
- сдвиг — по хэшам строк пикселей (FNV-1a), по **доле** совпавших строк (≥ 90 %), не по числу: строки «Screens Test Program NN» отличаются только цифрами, и ложный сдвиг на кратное высоте пункта выигрывал по числу — длина занижалась втрое;
- щелчки колеса — с паузой 60 мс (при 25 мс XP терял часть);
- на Win10 список, который помещается по высоте, но не по ширине, колесо крутит **по горизонтали** → сдвиг «не измерить», снимается одна страница (итог верный).

**Окно cmd** (`console.c`, сценарий `sync_time`):
- обычный интерактивный `cmd.exe` в **новой консоли** (`CREATE_NEW_CONSOLE`), папка `%USERPROFILE%` — с шапкой «Microsoft Windows…», как через «Выполнить». Команды **вводятся «с клавиатуры»** (`WriteConsoleInputW`, пары «нажата/отпущена») — видно «приглашение>команда» и вывод;
- с чужой консолью работает **помощник** — та же screens.exe с `/conhelper:<PID>` (`DETACHED_PROCESS`, затем `AttachConsole`): основной процесс сам консольный и не может прицепиться к другой консоли, не потеряв свою. Помощник пишет сообщения и текст консоли в `%TEMP%\screens_con_<PID>.txt` (UTF-16), основной процесс переносит его в журнал и удаляет. Коды помощника: 0 — успешно, 10 — аргументы, 11 — нет `AttachConsole`, 12 — нет доступа к CONIN$/CONOUT$, 13 — команда не завершилась (30 с), 14 — ввод не удался;
- команда выполнена, когда ввод разобран, у cmd **нет дочерних процессов** (`conhost.exe` не считается — на Win8+ живёт всё время) и курсор стоит 800 мс;
- **ширину консоли задавать при запуске**: на XP/7 консоль при сужении буфера обрезает уже выведенные строки (шапка Win7 становилась «All rights reserv»). Размер символа и рамка — от собственной консоли; `STARTF_USECOUNTCHARS` **вместе с** `STARTF_USESIZE` и `STARTF_USEPOSITION` (с одним буфером окно остаётся 80 столбцов). Шрифт: XP/7 — 8×12, Win10 — 8×16;
- XP «Дата и время»: вкладку «Время Интернета» XP добавляет через ~300 мс после появления окна — ждать до 3 с, пока `TCM_GETITEMCOUNT` (окно вкладок — `PSM_GETTABCONTROL`) ≥ 3, затем `PSM_SETCURSEL` 2 (по индексу — не зависит от языка). Меньше трёх (домен) или нет вкладок (нет прав) — закрыть и снимать без него;
- раскладка XP: cmd слева сверху, по содержимому; «Дата и время» под ним, правым краем к «Свойствам системы». 6.x+: cmd слева на всю высоту;
- на стенде служба W32Time на 7/10 остановлена — w32tm пишет «Служба не запущена (0x80070426)», это честный результат.

**Закрытие.** `WM_CLOSE` в обратном порядке; вопрос о сохранении — ответ «Нет» (`IDNO`); не закрылось за 5 с — `TerminateProcess`, только если процесс наш. **Сторожевой таймер** — отдельный поток: поднимает флаг прерывания (длинные шаги выходят), закрывает окна, курсор возвращает последним, код 1. Ctrl+C — то же.

**MMC — gpedit** (`mmc.c`, этап 4, готово 07.11.2026). Дерево читается через **специальные возможности Windows (MSAA, `oleacc`)**, а не через память процесса mmc.exe (от работы с чужой памятью отказались):
- `oleacc`/`ole32`/`oleaut32` подгружаются через `LoadLibrary` — список статических импортов exe не меняется (`IID_IAccessible` задан в коде, чтобы не тянуть `uuid.lib`); перед работой `CoInitializeEx`, в конце `CoUninitialize`.
- **MSAA показывает дерево плоско**: все видимые узлы — прямые дети клиентской области `SysTreeView32` (`AccessibleObjectFromWindow(OBJID_CLIENT)`), у самого узла детей нет. Навигация: найти нужный узел среди видимых по словарю (`names.c`, без учёта регистра, `ё`→`е`, точно или по началу), выделить (`accSelect` с `TAKEFOCUS|TAKESELECTION`), слать **`WM_KEYDOWN VK_RIGHT`** (только раскрывает, не сворачивает), пока не станет виден следующий узел пути (ленивое раскрытие, ждать до 5 с). Узел не найден — в журнал видимые узлы уровня, сценарий пропущен (код 1). MSAA работает и при разной разрядности процессов — отдельная сборка под разрядность mmc тут не нужна.
- На запуске MMC сам раскрывает дерево до «Конфигурация программ»; корневой узел («Политика "Локальный компьютер"») выделяем и раскрываем на всякий случай.
- Правая панель `SysListView32`: дождаться, пока число строк (`LVM_GETITEMCOUNT`) перестанет расти, подогнать столбцы `LVM_SETCOLUMNWIDTH` c `LVSCW_AUTOSIZE`/`LVSCW_AUTOSIZE_USEHEADER` — **значение (2-й столбец) видно целиком**, столбец названия сужается (как и в ручных примерах: там обрезано название). Ширины из `int`-сообщений, память чужого процесса не нужна.
- **Вид консоли**: MMC при закрытии пишет `%APPDATA%\Microsoft\MMC\gpedit` (положение окна, ширина столбцов). Файл читается **до** запуска и через `wnd_on_close` возвращается как был после закрытия (или удаляется, если его не было) — следов не остаётся.

**MMC — lusrmgr** (этап 5, план). Тем же способом (MSAA): узел «Пользователи»/«Группы». Группы: имя по SID — `LookupAccountSidW`; строку в `SysListView32` выделить, `VK_RETURN` → новый `#32770` того же PID; запасной путь — «Действие → Свойства».

## 11. Риски

- Антивирус (на объектах Kaspersky): эмуляция ввода (в том числе `AttachConsole` + `WriteConsoleInput` в сценарии `sync_time`), запуск своей копии с `/conhelper`, снимок экрана. Может понадобиться исключение или подпись exe. Записи в память чужого процесса утилита не делает: MMC читается через MSAA, раскрытие — `PostMessage(WM_KEYDOWN)`.
- Win11 с Windows Terminal по умолчанию: cmd откроется не в `ConsoleWindowClass` — сценарий `sync_time` не найдёт окно за 15 с.
- Названия узлов MMC в локализациях, которых нет в словаре — `/dump` и дополнение `names.c`.
- Медленные старые машины (список программ на XP, запуск mmc) — таймауты параметрами.
- Компонент `v141_xp` устаревший и может пропасть из установщика — тогда Build Tools 2022 из архива или MinGW-w64 (msvcrt; `-std=c99 -municode -D_WIN32_WINNT=0x0501 -static -Wl,--subsystem,console:5.01`, проверка импортов `objdump -p`).
